จากประสบการณ์ในการ Implement Project ที่เป็นธุรกิจ Project Based หนึ่งในความท้าทายของธุรกิจประเภทนี้คือ การคุมต้นทุนของ Project ให้ได้แบบ Real Time หรือเร็วที่สุดเท่าที่จะเร็วได้ เพื่อให้ผู้บริหารมองเห็นถึงกำไรก่อนที่จะขาดทุน

ดังนั้นในบทความนี้ อยากจะมาบอกเล่า และแชร์ประสบการณ์ในมุมมองของ Ecosoft ว่าเราสามารถช่วยแก้ปัญหาในจุดนี้ได้ยังไง

## ภาพรวมธุรกิจประเภท Project Based

![ภาพรวมธุรกิจประเภท Project Based](~/assets/images/post/project-based-business-with-odoo_1.png)

หัวใจสำคัญของธุรกิจ Project คือการคุมต้นทุนให้อยู่ ซึ่งแบ่งง่าย ๆ ได้เป็น 3 เรื่อง

1. คำนวณต้นทุนให้ถูกต้อง เพื่อให้คาดการณ์ได้ว่าจะมีกำไรเท่าไหร่
2. คุมต้นทุนไม่ให้เกินงบ ป้องกันไม่ให้ขาดทุน
3. ตรวจสอบความคืบหน้าของงานเทียบกับเงินที่เก็บได้ เพื่อประเมินความเสี่ยง Project นั้น ๆ

ทั้ง 3 ส่วนเชื่อมกันด้วยตัวเลขเดียวกัน คือต้นทุนที่ประเมินตอนขายจะกลายเป็น Budget ที่ใช้คุมงาน และเป็นฐานในการวัดความคืบหน้าในตอนท้าย

## คำนวณต้นทุนให้ถูกต้อง

<p className="-mt-4 text-xl text-muted">การประเมินต้นทุนจนถึงยืนยันใบเสนอราคา</p>

![การประเมินต้นทุนจนถึงยืนยันใบเสนอราคา](~/assets/images/post/project-based-business-with-odoo_2.png)

กระบวนการแรกเริ่มของการทำ Project จะต้องเริ่มด้วยการคำนวณต้นทุนให้ถูกต้อง เพื่อประเมินกำไรใน Project นั้น ๆ ซึ่งภายในจะแยกย่อยเป็น 3 ส่วนหลักคือ

1. การประเมินต้นทุน Project (Cost Estimation)

   ต้องรู้ต้นทุนที่จะเกิดขึ้นกับ Project นั้น เช่น ชั่วโมง/จำนวนคน ค่าบริการ หรือสินค้าที่จะขาย เพื่อให้เห็นต้นทุน และคำนวณกำไรได้

2. ปรับปรุงใบเสนอราคา (Revision)

   ในการขาย Project ก่อนที่ลูกค้าจะซื้อกับเรา อาจจะต้องมีการปรับปรุง หรือสร้างใบเสนอราคาที่มีหลายทางเลือกให้ลูกค้า ซึ่งต้นทุนในแต่ละแบบก็จะแตกต่างกันไป แต่เมื่อลูกค้าสนใจทางเลือกไหน และยืนยันแล้ว เอกสารใบเสนอราคาใบอื่นควรจะยกเลิกให้อัตโนมัติ เพื่อไม่ต้องนำไปใช้อีก

3. การเซ็นรับทราบและอนุมัติใบเสนอราคา (Sale Order)

   เมื่อลูกค้าเซ็นอนุมัติ ใบเสนอราคาจะกลายเป็น Sale Order และเป็นจุดเริ่มต้นของ Project

## คุมต้นทุนไม่ให้เกินงบ

<p className="-mt-4 text-xl text-muted">การคุมงบประมาณ และการใช้จ่าย</p>

![การคุมงบประมาณ และการใช้จ่าย](~/assets/images/post/project-based-business-with-odoo_3.png)

กระบวนการถัดมาหลังจากเริ่มต้น Project จะเป็นการคุมงบ และใช้จ่ายตามงบประมาณที่มี เพื่อให้เป็นไปตาม Scope of Work แบ่งออกเป็น 3 ส่วนหลักคือ

1. การคุมงบประมาณตามต้นทุน (Budget)
   - การใช้จ่ายที่เกี่ยวข้องกับ Project เช่น Expense, Purchase หรือการดำเนินการอื่น ๆ จะต้องอยู่ภายใต้งบประมาณที่กำหนด
   - สามารถปรับปรุงงบประมาณได้โดยคนที่มีสิทธิ์ ซึ่งจะทำให้กำไรของ Project นั้นลดลง
   - ผู้ใช้งานสามารถเห็นข้อมูลการใช้จ่ายได้แบบ Real Time

2. รายละเอียดงานของ Project
   - สร้าง Task และกระจายงาน
   - บันทึก Timesheet
   - บันทึก Expense ที่เกิดขึ้นระหว่างทำงาน

3. การส่งสินค้า (Delivery Order)
   - หาก Project มีสินค้าที่ต้องส่ง ระบบจะบันทึก Budget เป็น Stock Commit ตั้งแต่ขั้นตอนการหยิบสินค้า (Pick) เพื่อจองงบประมาณไว้
   - เมื่อมีการส่งสินค้าออกจริง ระบบจะบันทึกต้นทุนเป็น Actual ทันที
   - หากสินค้าไม่มีในคลัง ผู้ใช้งานจะต้องดำเนินการสั่งซื้อก่อน ซึ่งต้นทุนที่เกิดขึ้นจะถูกนำมาควบคุมภายใต้งบประมาณของ Project เช่นกัน

## ตรวจสอบความคืบหน้าของงานเทียบกับเงินที่เก็บได้

<p className="-mt-4 text-xl text-muted">Progress vs Billing</p>

![ตรวจสอบความคืบหน้าของงานเทียบกับเงินที่เก็บได้](~/assets/images/post/project-based-business-with-odoo_5.png)

#### เปรียบเทียบ % งาน, % งวดเงิน และ % ต้นทุน

ทุก Project ในระบบจะมีตัวเลข 3 ตัวที่ดูคู่กันเสมอ

- % งาน (Progress) มาจาก PM อัปเดตเองตามความคืบหน้าจริง
- % งวดเงิน (Invoice) มาจาก ยอดที่วางบิลจริง / มูลค่าสัญญา
- % ต้นทุน (Cost) ต้นทุนจริง / Budget

ตัวอย่าง: สัญญา 1,000,000 บาท Budget ต้นทุน 700,000 บาท สิ้นเดือนนี้

- PM แจ้งงานเสร็จ 40%
- วางบิลไปแล้ว 300,000 = 30%
- ต้นทุนจริง 350,000 = ใช้งบไป 50%

ทางบัญชีสามารถเลือกฐานในการปรับปรุงได้ 2 แบบคือ

1. Invoice & Progress

   ใช้ % งานจาก PM เทียบกับ % งวดเงิน<br />
   รายได้ที่ควรรับรู้ = 40% \* 1,000,000 = 400,000<br />
   วางบิลแล้ว 300,000<br />
   บันทึกรายได้ค้างรับ 100,000
   - เหมาะกับ Project ที่ต้นทุนไม่ได้เกิดตามเนื้องาน เช่น ต้องซื้อ Hardware ก้อนใหญ่ตั้งแต่ต้น ถ้าใช้ต้นทุนวัด % จะพุ่งเกินจริง

2. Invoice & Cost

   ใช้ % ต้นทุนเทียบกับ % งวดเงิน<br />
   ต้นทุนจริง = 50% \* 700,000 = 350,000<br />
   วางบิลแล้ว 300,000<br />
   ใช้เงินไปมากกว่าที่เก็บได้ 50,000
   - เหมาะกับ Project ที่ยังประเมินความคืบหน้าได้ไม่แม่นยำ หรือช่วงต้นของ Project เพราะเป็นวิธีที่ระมัดระวัง ใช้ตัวเลขจากระบบทั้งหมด ตรวจสอบย้อนกลับได้ ไม่ขึ้นกับการประเมินของคน

### ตัวอย่างหน้าต่างการติดตาม Project

![ตัวอย่างหน้าต่างการติดตาม Project](~/assets/images/post/project-based-business-with-odoo_4.png)

เมื่อกด Confirm ระบบจะสร้าง Journal Entry ตามส่วนต่างให้อัตโนมัติ โดยคู่บัญชีตั้งค่าได้ตามนโยบายบัญชีของแต่ละบริษัท และกลับรายการในวันแรกของเดือนถัดไป เพื่อให้สิ้นเดือนถัดไปคำนวณใหม่จากยอดสะสมโดยไม่นับซ้ำ

เมื่อมีทั้ง % งานและ % ต้นทุนอยู่คู่กัน ผู้บริหารจะเห็นทันทีว่าใช้เงินเร็วกว่างานหรือไม่

ในตัวอย่างนี้ งานไป 40% แต่ใช้งบไป 50% ถ้าอัตรานี้ต่อไปจนจบ ต้นทุนรวมจะอยู่ที่ประมาณ 350,000 ÷ 40% = 875,000 บาท เกิน Budget 175,000 และ Margin จะลดจาก 30% เหลือราว 12.5%

ทั้งนี้ตัวเลขเป็นการประมาณการเบื้องต้น ถ้า Project มีการซื้อของก้อนใหญ่ช่วงต้น % ต้นทุนจะนำหน้า % งานเป็นปกติ ผู้บริหารควรดูประกอบกับแผนต้นทุนของ Project นั้นด้วย

นี่คือสัญญาณที่เห็นได้ตั้งแต่กลาง Project ไม่ต้องรอปิดงานแล้วค่อยรู้ว่าขาดทุน

ธุรกิจ Project ไม่ได้ขาดทุนในวันที่ปิดงาน แต่ขาดทุนสะสมมาตั้งแต่วันที่ประเมินต้นทุนผิด ใช้งบเกินโดยไม่มีใครเห็น หรือเก็บเงินไม่ทันงาน

สิ่งที่เราออกแบบบน Odoo จึงเชื่อมทั้ง 3 ช่วงเข้าด้วยกัน

- ต้นทุนที่ประเมินตอนขาย กลายเป็น Budget ที่ใช้คุมงานจริง
- ทุกการใช้จ่าย ทั้งซื้อของ เบิกเงิน ค่าแรง และส่งสินค้า ถูกตัดจาก Budget ทันที
- ทุกสิ้นเดือน ผู้บริหารเห็น % งาน, % งวดเงิน และ % ต้นทุนคู่กัน พร้อมรู้ว่า Project ไหนกำลังหลุด Margin

ผลลัพธ์คือผู้บริหารรู้ว่า Project ไหนมีปัญหาตั้งแต่กลางทาง ยังมีเวลาแก้ ไม่ใช่รู้ตอนปิดงบปลายปี

ทั้งหมดนี้คือประสบการณ์ที่เราสั่งสมร่วมกับ Partner จนพัฒนาเป็น Product ที่ตอบโจทย์การทำงานจริงของธุรกิจ Project หากต้องการสอบถาม พูดคุยหรือแลกเปลี่ยนประสบการณ์สามารถสอบถามได้เลยครับ
